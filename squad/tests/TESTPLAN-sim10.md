# SIM 10 테스트 시나리오 (정예 좀비를 캠페인에 반영)

이 문서는 **테스트를 대신 돌려 줄 세션(Sonnet)에 그대로 건네는 지시서**다. 코드·보정 표는 이미 바뀌어 있고, 테스트는 아직 한 번도 돌리지 않았다.

## 무엇이 바뀌었나

- `assets/core.js`: `SIM` 9 → 10. 캠페인에 정예 좀비 — 오염 좀비 L11(`UNLOCK.toxic`)부터, 분열 좀비 L21(`UNLOCK.split`)부터. 레벨 생성이 끝난 뒤 `placeElites`가 졸개 몇을 정예로 바꾼다(자리·수는 그대로, 체력과 `f.elite`만).
- `assets/caltable.js`, `assets/cyctable.js`: SIM 10으로 다시 만든 보정 표(손으로 고치지 않는다).
- `assets/main.js`: 레벨 카드 문구(L11·L21). `sw.js`: 캐시 `squad-v2.16.0`.
- `tests/endgame.mjs`: 고정 해시(`BASE_HASH`)를 SIM 10 값으로 바꿨고, 맨 아래에 '캠페인 정예(SIM 10)' 테스트 6개를 새로 썼다(**돌려 보지 않았다 — 테스트 쪽이 틀렸을 수 있다**).

## 돌릴 것 (순서대로, `Webpages/` 에서)


## 시나리오와 판단 기준

**A. 새 테스트(2번) — 캠페인 정예**

| # | 테스트 이름(앞부분) | 확인하는 것 | 실패하면 |
|---|---|---|---|
| A1 | 1회차 캠페인의 stateHash | `SIM === 10`, 고정 해시 1053165989 | 해시만 다르면 누군가 표·규칙을 건드린 것. 값을 새로 적지 말고 무엇이 달라졌는지 보고 |
| A2 | L10까지는 없고, L11부터… | L1~10 정예 없음, L11 오염 ≥1, L21 둘 다 ≥1, 정예 ≤ 졸개의 35%, 없는 레벨 비율 | 기대값 표와 견줘 테스트의 띠가 틀렸으면 테스트를, 정예가 정말 안 나오면 `placeElites`를 |
| A3 | 배치는 SIM 9 그대로 | 정예를 끈 레벨과 줄·소품·톱날·골든·적 자리가 같고 정예 체력만 ×배수 안 | 자리가 다르면 **코드 버그**(정예 배치가 레벨 난수를 건드렸다) — 보고 |
| A4 | 정예 체력은 상한이 있다 | 정예 체력 ≤ max(원래 체력, cap × 골든 병력 × 10) | 반올림 차 1을 넘으면 `setElite` 확인 |
| A5 | 실제 판에서 웅덩이·분열 | L3·7·10 판에 `s.pools` 없음, 7개 레벨에서 웅덩이 ≥5·분열 ≥3, 웅덩이가 있는 틱의 저장·복원이 같은 해시 | 횟수 미달이면 실제 횟수를 적어 보고(띠 조정 후보). 해시가 갈라지면 **코드 버그** |
| A6 | 공정성: 예고 ≥ 비켜서는 시간 | 웅덩이마다 `T ≥ 1초`, `T ≥ min(왼쪽·오른쪽으로 비켜서는 시간, 3초) − 0.05` | 어긋난 한 건의 숫자(병력·x·웅덩이 x·T)를 그대로 보고. 테스트의 계산과 `eliteDeath`의 계산 중 어느 쪽이 다른지 확인 |
| A7 | 난이도: 승률·웅덩이 손실 | sloppy0.1 승률 55~98%(기대 84%), 웅덩이 손실 > 0 이고 전체의 25% 이하, 가만히 서서 0승 | 기대값과 크게 다르면(±10%p) 보정 표가 코드와 안 맞는 것 — 보고 |

**B. 예전부터 있던 테스트(3번) — 걸릴 수 있는 곳**

| 묶음 | 걸릴 수 있는 까닭 | 판단 |
|---|---|---|
| `run.mjs` '보정 표'(표와 실제 보정이 같다, `CAL.sim`) | 표를 만든 뒤 `core.js`를 또 고쳤다면 어긋난다 | 어긋나면 표를 다시 만든다(아래 명령). 손으로 고치지 않는다 |
| `run.mjs` 밸런스 띠(승률·별·지원·판돈·손실 원인 비율) | 정예로 L11+가 조금 어려워졌다(집중 봇 90 → 80%) | 띠를 **넓히지 말고** 실패한 테스트 이름·기대 띠·실제 값을 표로 보고. 사람이 띠를 옮길지 정예를 약하게 할지 정한다 |
| `run.mjs` 'SIM 9 배치는 SIM 8 배치 그대로'·'소개 항목(missing)' | 정예는 `bare`에도 똑같이 들어가 통과해야 한다 | 실패하면 **코드 버그** 후보 — 보고 |
| `run.mjs` 이어하기·스냅숏 | SIM이 올라 옛 스냅숏을 버리는 경로 | 실패 내용 보고 |
| `endgame.mjs` 회차 표(`CYC.sim`, 표본 보정 일치)·회차 벤치 띠 | 2·3회차도 정예가 들어갔다 | 표 불일치는 다시 만들기, 띠는 보고 |
| `endgame.mjs` 무한모드 묶음 | 이번에 무한모드 규칙은 안 바꿨다 — 그대로 통과해야 한다 | 실패하면 보고(캠페인 변경이 새어 들어간 것) |
| 그림 테스트 묶음 | 그림은 안 바꿨다 | 통과해야 한다 |

표를 다시 만들어야 할 때만(9분 + 3분, 4코어):

```bash
git show a637880:squad/assets/caltable.js > /tmp/caltable.sim9.js      # SIM 9 표(배치를 지키는 기준)
node -e "import('/tmp/caltable.sim9.js').then(m=>require('fs').writeFileSync('/tmp/expect9.json',JSON.stringify({expect:m.CAL.expect})))"
node squad/tools/caltable.mjs --expect /tmp/expect9.json --keep ../../../tmp/caltable.sim9.js
node squad/tools/cyctable.mjs
```

표를 다시 만들면 `BASE_HASH`도 달라질 수 있다 — 그때는 A1의 식을 그대로 돌린 값을 적고, 다시 만든 까닭과 함께 보고한다.

## 규칙

- 테스트를 건너뛰거나(`skip`·`todo`) 지우지 않는다. 띠·기대값은 **새로 쓴 A 묶음의 명백한 테스트 오류**일 때만 고치고, 고친 줄과 까닭을 적는다.
- `VERSION`·`SIM`·`ELITE`·`POOL_*`·`UNLOCK` 값은 바꾸지 않는다(바꾸면 표가 무효다). 바꿔야 한다고 보면 고치지 말고 보고한다.
- 커밋·푸시는 하지 않는다. 마지막에 아래 형식으로만 보고한다.

## 보고 형식

1. 묶음별 통과/실패 수(문법, endgame, run, 그림).
2. 실패한 테스트마다: 이름, 기대, 실제, 원인 판단(테스트 오류 / 코드 버그 / 밸런스 띠 / 표 불일치), 한 일.
3. 고친 파일과 줄.
4. 사람이 정해야 할 것(띠를 옮길지, 정예 수치를 바꿀지).
